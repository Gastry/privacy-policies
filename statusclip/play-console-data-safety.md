## ASO and policy strategy

Use a clear, policy-safe listing:

- Main keyword cluster: status saver, save status, status photos, status videos, gallery.
- Avoid risky wording: "WhatsApp Downloader", "hidden status", "spy", "recover deleted status", "official".
- Mention WhatsApp only descriptively in the body, never as affiliation.
- Lead with the most concrete value: save viewed status photos and videos to the gallery.
- Keep the first 2-3 lines of the long description useful because many users do not expand further.

Official limits to respect:

- App name: 30 characters.
- Short description: 80 characters.
- Full description: 4000 characters.

### Data safety

Reason:

- No `INTERNET` permission.
- No developer-owned backend.
- No ads, analytics, tracking SDKs, account login or billing.

If Play Console asks whether data is collected:

- Answer: No.

If Play Console asks about security practices:

- Data encrypted in transit: Not applicable because the app does not transmit collected user data to developer servers.
- Users can request deletion: Not applicable for server-side data because the app has no account or developer server data. Local data can be deleted by clearing app data or uninstalling the app.

### Photo and video permissions declaration

Permissions present:

- `READ_MEDIA_IMAGES`
- `READ_MEDIA_VIDEO`
- `READ_MEDIA_VISUAL_USER_SELECTED`

Suggested declaration text:

StatusClip's core feature is to show and save status photos and videos that the user has already viewed and that are available locally on the Android device. The app needs frequent local access to photos and videos so it can display recent status media, generate previews, play videos, save selected statuses to the user's gallery, share selected media when the user requests it, and support the optional auto-save feature.

The app does not upload photos or videos to developer-owned servers, does not use ads or analytics SDKs, and does not sell or share user media. Access is limited to user-facing local status saving features.

Why the Android Photo Picker is not enough:

The app is not a one-time picker flow. Its main screen must repeatedly show locally available status media and refresh it, including optional auto-save for newly detected local statuses. A one-time picker would not support the main gallery and auto-save behavior.

### Foreground service declaration

Foreground service type:

- `dataSync`

Suggested declaration text:

StatusClip uses a foreground service only when the user enables optional auto-save. While active, the service periodically checks local status media that is already available on the device and saves newly detected statuses to the user's gallery. Android shows a persistent notification while the service is running, and the user can turn auto-save off in the app settings or stop it from the notification.

User impact if delayed or interrupted:

Statuses are temporary. If auto-save is delayed or stopped, a status may disappear from the local status folder before the user manually saves it. The user can still save statuses manually from the app when available.

Why foreground service is appropriate:

The work is user-visible, optional, and controlled by a persistent notification. It processes local files on device and avoids hidden background behavior.
